# AI Hallucination Detection and Verification System

## Using Large Language Models, Retrieval-Augmented Generation, and Multi-Agent AI

---

## 1. Project Overview

Large Language Models (LLMs) such as GPT, Gemini, and Llama can generate fluent and informative responses. However, they may sometimes produce incorrect, fabricated, or unsupported information. These incorrect outputs are commonly referred to as **hallucinations**.

This project proposes an **AI Hallucination Detection and Verification System** that detects and verifies potentially hallucinated information generated by Large Language Models.

The proposed system combines:

- Large Language Models (LLMs)
- Retrieval-Augmented Generation (RAG)
- Multi-Agent AI
- External knowledge sources
- Hallucination detection techniques
- Evidence-based verification

The system analyzes an LLM-generated response, identifies factual claims, retrieves relevant evidence, and determines whether the generated information is supported, contradicted, or unsupported by reliable sources.

---

## 2. Abstract

Large Language Models have demonstrated significant capabilities in natural language understanding and generation. However, these models can generate hallucinated information that appears factually correct but is not supported by reliable evidence.

The objective of this project is to develop an AI-based system for detecting and verifying hallucinations in LLM-generated responses. The proposed system integrates Retrieval-Augmented Generation (RAG) with a Multi-Agent AI architecture to improve the reliability and interpretability of hallucination detection.

The system analyzes the generated response, identifies factual claims, retrieves relevant information from trusted sources, and evaluates whether the claims are supported, contradicted, or unsupported by the retrieved evidence.

The project uses the **RAGTruth hallucination corpus** as an important research and evaluation resource. Additional techniques inspired by **SelfCheckGPT** and other recent hallucination evaluation research will also be considered.

The final system aims to provide users with an understandable verification result showing the generated response, detected claims, supporting evidence, hallucination status, and an overall reliability score.

---

## 3. Problem Statement

Large Language Models can generate responses containing:

- Factually incorrect information
- Unsupported claims
- Fabricated facts
- Incorrect numerical information
- Misleading statements
- Information that cannot be verified from reliable sources

Traditional text-generation evaluation methods are not sufficient to determine whether every factual claim in a response is correct.

Therefore, there is a need for an automated system that can:

1. Detect potentially hallucinated content.
2. Identify individual factual claims.
3. Retrieve relevant supporting information.
4. Compare generated claims with retrieved evidence.
5. Determine whether claims are supported or contradicted.
6. Provide an interpretable verification result.

## 5. Existing System

Existing hallucination detection approaches include:

### Model-Based Detection

A separate language model can evaluate whether a generated response is factually reliable.

### Self-Consistency Based Detection

Methods such as **SelfCheckGPT** analyze multiple generated responses and identify inconsistencies between them.

### Retrieval-Based Verification

Generated information can be compared with information retrieved from external knowledge sources.

### Dataset-Based Evaluation

Research datasets such as **RAGTruth** can be used to train and evaluate hallucination detection systems.

However, individual approaches may have limitations related to:

- Lack of external evidence
- Limited interpretability
- Difficulty detecting individual hallucinated spans
- Dependence on a particular evaluation model
- Difficulty handling complex factual claims

## 6. Proposed System

The proposed system combines **LLMs, RAG, and Multi-Agent AI** to perform hallucination detection and verification.

The general workflow is:

```text
User Query
    |
    v
Large Language Model
    |
    v
Generated Response
    |
    v
Claim Extraction
    |
    v
Multi-Agent Verification
    |
    +----------------------+
    |                      |
    v                      v
Evidence Retrieval     Response Analysis
    |                      |
    v                      v
Retrieved Evidence    Claim Evaluation
    |                      |
    +----------+-----------+
               |
               v
       Verification Agent
               |
               v
     Hallucination Detection
               |
               v
      Final Verification Result
```

The system attempts to provide evidence along with the hallucination detection decision instead of simply returning a binary result.

## 7. System Architecture

The proposed architecture consists of the following major components:

### 7.1 User Interface

The user provides a question or prompt to the system.

### 7.2 Large Language Model

An LLM generates an initial response to the user's query.

### 7.3 Claim Extraction Module

The generated response is divided into individual factual claims that can be verified.

### 7.4 Retrieval Module

Relevant documents or information are retrieved from available knowledge sources.

### 7.5 Multi-Agent Verification Layer

Specialized AI agents analyze different aspects of the response and evidence.

### 7.6 Evidence Evaluation

Generated claims are compared against retrieved information.

### 7.7 Hallucination Detection

The system determines whether individual claims are supported, contradicted, or unsupported.

### 7.8 Final Result

A verification report is generated containing:

- Generated response
- Individual claims
- Retrieved evidence
- Verification status
- Confidence/reliability information

## 8. Multi-Agent Architecture

The proposed system uses multiple specialized agents to perform different verification tasks.

### Query Analysis Agent

- Understands the user's query.
- Identifies important entities and concepts.
- Prepares the query for retrieval.

### Claim Extraction Agent

- Analyzes the generated response.
- Identifies factual statements.
- Divides the response into verifiable claims.

### Retrieval Agent

- Searches relevant knowledge sources.
- Retrieves documents related to each claim.
- Provides evidence for verification.

### Evidence Verification Agent

- Compares generated claims with retrieved evidence.
- Determines whether evidence supports or contradicts the claim.
- Identifies unsupported information.

### Hallucination Detection Agent

- Analyzes verification results.
- Identifies potentially hallucinated claims.
- Produces hallucination-related classifications.

### Review Agent

- Reviews the decisions made by other agents.
- Identifies inconsistent results.
- Improves the reliability of the final decision.

## 9. RAG-Based Verification

**Retrieval-Augmented Generation (RAG)** is used to provide external evidence for verifying generated information.

The basic verification process is:

```text
User Query
    |
    v
Generated Response
    |
    v
Claim Extraction
    |
    v
Information Retrieval
    |
    v
Relevant Documents
    |
    v
Evidence
    |
    v
Claim Verification
```

Instead of relying only on the knowledge stored inside the LLM, the system retrieves relevant information from external knowledge sources.

The retrieved evidence is then used to determine whether the generated claims are supported or contradicted.

## 10. Hallucination Detection and Verification

The proposed system follows these major steps:

### Step 1: User Query

The user submits a question or information request.

### Step 2: Response Generation

An LLM generates a response to the query.

### Step 3: Claim Extraction

The generated response is divided into individual factual claims.

### Step 4: Evidence Retrieval

Relevant information is retrieved for each claim.

### Step 5: Evidence Comparison

The generated claims are compared with the retrieved information.

### Step 6: Claim Classification

Each claim can be classified as:

- **Supported** – Retrieved evidence supports the generated claim.
- **Contradicted** – Retrieved evidence conflicts with the generated claim.
- **Unsupported** – Sufficient evidence could not be found to verify the claim.

### Step 7: Final Verification

The system generates an overall reliability assessment and highlights potentially hallucinated claims.

## 11. RAGTruth Dataset

The project uses the **RAGTruth** dataset as an important research and evaluation resource.

RAGTruth is a hallucination corpus designed for developing trustworthy Retrieval-Augmented Language Models.

It contains naturally generated responses with human annotations identifying hallucinated content at the response and span levels.

### RAGTruth will be used for:

## 15. Evaluation

The system will be evaluated using suitable classification and hallucination detection metrics.

### Precision

Measures how many detected hallucinations are actually hallucinations.

```text
Precision = TP / (TP + FP)
```

### Recall

Measures how many actual hallucinations were successfully detected.

```text
Recall = TP / (TP + FN)
```

### F1-Score

Provides a balance between precision and recall.

```text
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

### Accuracy

Measures the percentage of correctly classified instances.

```text
Accuracy = Correct Predictions / Total Predictions
```

Where appropriate, both **response-level** and **span-level** detection will be considered.
